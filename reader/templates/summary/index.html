分层与记账口径
  • S = Summary 层，不是分级 L：S3 单篇 → S2 按源 → S1 按分类 → S0 全局； 分级是 L0 忽略 / L1 低价值·普通 / L2 关注 / L3 重点。
  • S3 单篇压缩（正文 > {{ cfg.s3 }} 字）：单独一次调用，产出 100–200 字摘要 → 记在该 feed 上。
  • S2 按源汇总（单源 ≥ {{ cfg.s2 }} 条）：同主题合并去重 → 记在该 feed 上。
  • S1 按分类汇总（分类内 ≥2 源或 ≥5 条）：跨源合并 → 记在该分类上。
  • S0 全局合成：整份日报 → 记为公共开销（不分摊到任何 feed/分类）；S0 不缓存。
  • 单源条目过多（> {{ cfg.feed_max }} 条）时只丢 L1：每源保留最近 {{ cfg.feed_l1_keep }} 条， L2/L3 一条不丢；只影响日报素材，不标已读、不删源。
  • 先规则后 LLM：转贴 / ^回复@ / 标题流三类在进模型前先压成一句话 （是压正文，与级别无关），调用量约为全量的 1/3。 长转贴（正文 > 120 字）不压 —— 该砍的是噪声，不是信息。
  • 分级 L0 的条目不进总结（已被"标已读"过滤），fail-open 落 L0 的也不进。
  • 引用只带 [源名 · 时分]；报告头部给要点引用（每个要点是否点得回原文），不再堆一整段来源索引。
  • S3/S2/S1 默认按输入指纹复用缓存（TTL {{ cfg.cache_ttl }} 天）；输入变了（新文章 / 分级调整 / prompt 改动）自动重跑。 详情页可「忽略缓存重跑」。
  • 预算用尽或模型全挂时自动降级为规则版报告 —— 统计与异常段一定在，内容退化为条目清单。
  • 日报与周报在同一条列表里：按截至日倒序，同一天周报在上。两者的运行记录在 SummaryRun 里用 kind 区分（共用 id 池），所以周报的钱与 token 也和日报一样按行记账；失败的周报照样列在这里、照样能重跑。
  • 「规模」列两类口径不同：日报是「当天条目数 · 当天原始异常数」；周报是 「拼进来的日报份数 · 7 天原始异常之和」。跨度不同，别拿周报的数和单日直接比。

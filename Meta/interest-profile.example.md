# 读者画像（分级与日报札记共用的全局依据）——示例模板

> 用法：`cp Meta/interest-profile.example.md Meta/interest-profile.md`，然后把下面
> 的示例人设换成你自己。**本文件是所有源共用的全局层**：只回答「读者是谁、
> 什么对他有价值」；不写这个文件系统也能跑（分级走零成本默认路径），只是
> LLM 判定少一层「你是谁」的依据。
>
> 两个使用方：① **分级**——判断一条内容命中哪条需求，定 L0–L3；
> ② **日报札记**——判断进了日报之后哪几条更值得先看，抽至多 3 件并各带引用。
>
> ★★ **不要在这里写任何单一分类的判据**——投资、技术各自的 L0–L3 判据在
>   阅读器的分级配置页（`/triage/config`）里维护。画像会被 `{profile}` 占位符
>   拼进**每一个**源的 prompt：写在这里的判据等于全局判据，会污染别的分类
>   （真实踩过的坑：画像里的投资判据曾泄漏进兼职信息类源的判定）。

## 读者（多重身份并存，不排序）

下面是一份**虚构示例**：按你自己的情况重写，身份条数随意。

1. **技术**——后端 / 基础设施工程师，数据库、存储与可观测性是老本行；
   当前关注 LLM 在后端业务里的落地（RAG、agent 编排、推理成本）。
   要的是**能改判断、或能上手用**的东西，不要科普。
2. **投资者**——指数基金与红利股为主，长期持有 + 少量波段；
   关注利率、宏观数据与消费 / 公用事业行业的基本面变化。
3. **家长**——孩子刚上幼儿园，关心科学的育儿方法与亲子沟通，
   反感制造焦虑的升学营销。
4. **生活**——跑步与力量训练爱好者，自己做饭；关注运动损伤预防
   与家用器械选购。

★ 判定一条内容时问的是**「它命中上面哪一条需求」**，不按单一身份排座次。
与所有条目都对不上，才是它该被忽略的理由——而不是"因为读者是工程师，
所以这条投资内容无关"。

## 什么对他有价值

- **能改变判断的**：新的产业 / 政策 / 数据事实；对手边技术或投资决策
  有实质性影响的分析
- **能直接行动的**：可复用的方法与工具；有明确的对象、时间、数字的信息
- **他正在做的事**：LLM 落地项目、基金定投调整、训练计划

## 什么对他没价值

- **情绪与社交**：焦虑、迷茫、抱团取暖、口水仗
- **纯自述**：晒能力 / 晒经历，落点在自我推销（≠ 分享可复用的方法）
- **无增量的重复**：旧闻转载、回忆怀旧
- **纯生活记录**：打卡、日常随笔（不含可行动信息）
- **营销与软文**：干货外壳，落点在卖课、导流
- **泛泛而谈**：落不到具体人 / 事 / 物 / 时间的原则性表述

## 与底座、分类的分工（不要在本文件里越界）

- 「L0–L3 各自意味着什么」「投票与 anti-FOMO」「输出 JSON 格式」由代码底座
  `BASE_RULES` 全权负责，**本文件不重复定义**。
- 某一类内容具体判哪一级，由**分类配置 → 本源配置**决定；
  本文件只提供读者侧的「有没有价值」判断，不提供「算哪级」的判据。
- 长度硬约束：**≤ 2000 字符**（润色路径 `profile_text()[:2000]` 会静默截断尾部）。
